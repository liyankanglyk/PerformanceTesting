# 系统需求文档

## 系统名称
**速购商城性能测试系统**

## 一、基础概况
1. 项目类型：SpringBoot 单体项目，非前后端分离，单工程运行打包
2. 运行方式：IDEA 一键启动，可打包 Jar 包独立部署服务器
3. 用途：专供 JMeter 性能压测练习，覆盖登录、查询、并发下单业务场景
4. 压测规格：支持 300 用户并发访问
5. 通信协议：HTTP

## 二、技术架构
- 核心框架：SpringBoot 3.4.6
- 持久层：MyBatis-Plus 3.5.11（含 mybatis-plus-jsqlparser 分页插件）
- 数据库：MySQL 8.0
- 接口文档：springdoc-openapi 2.8.5 (OpenAPI 3 / Swagger UI)，入口 /doc.html 自动跳转
  > Knife4j 4.5.0 内置 springdoc 2.3.0，与 Spring Boot 3.4（Spring Framework 6.2）二进制不兼容，
  > 访问 /v3/api-docs 会抛 NoSuchMethodError 导致文档页 500，因此改用官方 springdoc。
- 身份校验：JWT Token (jjwt 0.12.6)，有效期 1 小时
- 密码加密：MD5(明文 + 时间戳) 加盐传输
- 前端：纯 HTML + CSS + JS，非前后端分离

## 三、业务流程

### 用户端
用户登录鉴权 → 模糊搜索查询商品 → 并发执行商品下单 → 按需查询个人订单

### 管理端
管理员登录 → 系统概览看板 → 用户/商品/订单 CRUD 管理 → 操作日志追溯

## 四、系统角色

| 角色 | role 值 | 权限范围 |
|------|:------:|------|
| 普通用户 | 0 | 浏览商品、下单购买、查看个人订单 |
| 管理员 | 1 | 用户管理、商品管理、订单管理、系统状态监控、操作日志查看 |

## 六、业务规则
1. 登录请求头携带时间戳 ts，密码按 MD5(明文+时间戳) 加盐校验，登录成功返回 JWT 令牌及角色信息
2. 除登录接口外，所有业务接口必须携带有效 Token，无效令牌直接拦截
3. 管理端接口额外校验角色，非管理员返回 403
4. 商品查询接口支持 keyword 模糊搜索，不传参数时返回全部数据
5. 下单校验用户权限与商品库存，使用数据库原子 UPDATE 扣减库存，支持高并发争抢场景
6. 管理员操作（登录、用户/商品/订单 CRUD）自动记录到 operation_log 表；日志必须可审计：记录操作人、目标记录 ID 与名称、字段变更前后（如 `单价 100.00→66.60；库存 3→0`），登录记来源 IP；不写入明文密码，失败的变更不记日志
7. 管理端写接口先校验参数再落库：username/password 必填且不超列宽，role 只能 0/1，goodsName 必填，price ≥ 0 且不超 DECIMAL(10,2)，stock ≥ 0；校验失败返回 code=400 + 明确 msg
8. 管理员账号保护：不能删除当前登录账号、不能删除或降级最后一个管理员；已有订单的用户/商品不允许删除（避免 orders 表出现无效 user_id / goods_id）——需先在订单管理里删除对应订单（`DELETE /orders/{id}` 或 `DELETE /orders?userId=|goodsId=`）
9. 标记订单支付为条件更新（status 0 -> 1），重复调用返回失败且不重复写日志；操作日志写入失败不影响主业务
10. 管理接口除校验 Token 角色外，还回查数据库真实角色：被降级或已删除的账号，其旧 Token 立即失效（403 / 401）
11. 管理端四个列表（用户 / 商品 / 订单 / 操作日志）均为服务端分页（page 从 1 开始，size 默认 10、上限 200；响应 `data={records,total,page,size,pages}`；越界页返回空列表但 total 正确），依赖 MyBatis-Plus 分页插件 + mybatis-plus-jsqlparser
12. 密码摘要固定按 UTF-8 计算 MD5，与前端 js 实现一致（中文用户名/中文密码可正常登录）
13. 系统概览页为压测看板：一次 `GET /admin/summary` 返回业务计数、近 N 分钟下单/支付速率、库存与 JVM（堆使用率进度条 + 趋势 + GC + 线程峰值）；默认 5 秒自动刷新（可关 / 10s / 30s），离开该面板或标签页隐藏时自动停轮询，两项设置记在 localStorage；速率窗口可选 1/5/15 分钟
14. 数字参数类型不匹配返回 HTTP 400 + `invalid parameter: <参数名>`（此前是 500，且把 Java 转换异常原文透出给前端）
15. 压测数据准备：`db.init-mode`（always / if-absent / never）控制启动时是否清库重建，默认 always 保持历史行为；跑完一轮想重新灌数据不用重启服务，点系统概览页的「系统重置」（`POST /admin/db/reset?confirm=RESET`，破坏性、需显式确认、并发只允许一个、执行本身写 `DB_RESET` 审计）；`db.reset.enabled=false` 可整体关闭
16. SQL 脚本固定按 UTF-8 读取，数据源 URL 显式带 `characterEncoding=UTF-8`：中文 Windows 的平台默认字符集是 GBK，不指定就会把 `data.sql` 里的中文灌成「鑻规灉」这类乱码（Java 18+ 才默认 UTF-8，本项目跑 Java 17）

## 七、接口列表

### 用户端 API（基础路径 /api）
| 方法 | 路径 | 说明 | Token |
|------|------|------|:---:|
| POST | /user/login | 用户登录，返回 token + role | ✗ |
| GET | /user/info | 获取当前用户信息 | ✓ |
| GET | /goods/list | 查询商品（?keyword= 模糊搜索） | ✓ |
| POST | /order/buy | 提交商品下单 | ✓ |
| GET | /order/list | 查询个人订单 | ✓ |

### 管理端 API（基础路径 /api/admin）
| 方法 | 路径 | 说明 |
|------|------|------|
| GET | /status | 系统运行状态（内存、线程、运行时间、GC、堆使用率） |
| GET | /summary | 系统概览汇总：业务计数 + 近 N 分钟速率 + 库存 + JVM（`?windowMinutes=`，默认 5，夹 1-60） |
| GET | /logs | 操作日志（?keyword=&action=&limit=，默认 100 条，上限 1000） |
| GET | /log-actions | 日志中出现过的操作类型（供筛选） |
| GET | /users | 用户列表（分页 ?page=&size=，默认 20 条/页，上限 200） |
| POST | /users | 新增用户 |
| PUT | /users/{id} | 编辑用户 |
| DELETE | /users/{id} | 删除用户 |
| GET | /goods | 商品列表（管理端专用） |
| POST | /goods | 新增商品 |
| PUT | /goods/{id} | 编辑商品 |
| DELETE | /goods/{id} | 删除商品 |
| GET | /orders | 全部订单列表（分页 ?page=&size=&status=） |
| PUT | /order/pay/{orderNo} | 确认支付订单（**用户端**，只能付自己的单） |
| POST | /user/logout | 退出登录（写审计日志） |
| GET | /admin/db/state | 数据库初始化状态（启动策略 / 能否手动重置 / 上次重置） |
| POST | /admin/db/reset | **系统重置**（破坏性）：重建四张表 + 灌初始数据，需 `confirm=RESET` |
| DELETE | /orders/{id} | 删除订单 |
| DELETE | /orders?userId=\|goodsId= | 批量清理某用户/某商品的订单 |

### 页面清单
| 页面 | 路径 | 说明 |
|------|------|------|

- 主色：#1677FF（蓝色）
- 布局：用户端居中卡片式，管理端侧边栏 + 内容区

### 管理后台面板
| 面板 | 功能描述 |
|------|------|
| 系统概览 | 业务数据（订单总数、已支付 + 支付率、近 N 分钟下单速率、用户数、商品与库存、日志量；卡片可点直达对应面板）+ JVM（堆使用率进度条与趋势、GC 次数/耗时、线程当前/峰值、运行时间、非堆、CPU 核心数）+ 最近操作摘要；自动刷新默认 5s，速率窗口可选 1/5/15 分钟；工具条右侧只有一个「系统重置」按钮（需输入 RESET 确认） |

| 商品管理 | 商品列表、新增商品、编辑价格库存、删除商品 |
| 订单管理 | 全部订单查看、标记未支付订单为已支付 |
| 操作日志 | 管理员操作记录，含操作人、操作类型、详情（目标与变更前后）、时间；支持按关键词/操作类型筛选与条数上限 |

## 十、运行部署要求
1. 本地开发：IDE 直接启动主类即可正常提供接口服务与页面访问
2. 生产部署：`mvn clean package -DskipTests` 打包 Jar，`java -jar` 运行
3. 项目启动后可访问在线接口文档（/doc.html → Swagger UI），支持接口调试查看
4. 静态页面由 SpringBoot 内置 Tomcat 直接托管，无需额外 Web 服务器
5. 每次启动自动执行数据库初始化：删除旧表 → 创建新表 → 插入初始测试数据
